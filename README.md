# Backend

Серверная часть приложения разработана на **Go** с использованием стандартного пакета `net/http`. Архитектура построена по принципам многослойного приложения (Layered Architecture), что обеспечивает разделение ответственности между компонентами и упрощает сопровождение проекта.

## Возможности

- Загрузка конфигурации из `.env`
- Подключение к PostgreSQL
- Логирование работы приложения
- JWT-аутентификация и авторизация
- Middleware для обработки HTTP-запросов
- Разделение бизнес-логики и работы с базой данных
- Поддержка миграций базы данных

---

## Архитектура проекта

```
.
├── cmd/

```

## Слои приложения

### Config

Отвечает за:

- загрузку переменных окружения;
- настройку параметров сервера;
- конфигурацию подключения к базе данных;
- настройку JWT;
- инициализацию логирования.

---

### Database

Выполняет:

- подключение к PostgreSQL;
- проверку соединения;
- настройку пула соединений;
- запуск SQL-миграций;
- мониторинг состояния подключения.

---

### Repository

Слой доступа к данным.

Вся работа с SQL-запросами сосредоточена в репозиториях, что позволяет полностью отделить бизнес-логику от хранения данных.

---

### Service

Содержит основную бизнес-логику приложения.

Сервисы получают данные из репозиториев, выполняют необходимые вычисления и проверки, после чего возвращают результат обработчикам.

---

### Handler

Обрабатывает HTTP-запросы:

- получает данные клиента;
- выполняет валидацию;
- вызывает сервисный слой;
- формирует HTTP-ответ.

---

### Middleware

Перед обработкой каждого запроса выполняется цепочка middleware.

Основные задачи:

- проверка JWT-токена;
- настройка CORS;
- логирование запросов.

---

## Запуск приложения

При старте приложения выполняются следующие действия:

1. Загрузка конфигурации.
2. Инициализация логирования.
3. Подключение к базе данных.
4. Создание репозиториев.
5. Инициализация сервисов.
6. Регистрация обработчиков.
7. Подключение middleware.
8. Запуск HTTP-сервера.

## Принципы разработки

Проект построен с использованием следующих принципов:

- Layered Architecture
- Separation of Concerns
- Dependency Injection
- Repository Pattern
- Service Layer Pattern
- Middleware Pattern

---

## Конфигурация

Настройки приложения считываются из файла `.env`.

Основные параметры:

- порт HTTP-сервера;
- параметры подключения к PostgreSQL;
- секретный ключ JWT;
- время жизни access и refresh токенов.

---

## База данных

Для хранения данных используется PostgreSQL.

Структура базы данных управляется с помощью SQL-миграций, которые создают необходимые таблицы и индексы при развертывании приложения.

---

## Логирование

Для записи информации о работе приложения используется библиотека **Logrus**.

Логируются:

- запуск приложения;
- подключение к базе данных;
- HTTP-запросы;
- ошибки выполнения.
